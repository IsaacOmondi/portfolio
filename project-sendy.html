Sendy Middleware Architecture

Node.js Middleware Chapter Lead

Apr 2019 - Aug 2023 · Nairobi, Kenya

Overview

Sendy Limited is a logistics platform serving East Africa. I joined as the Node.js Middleware Chapter Lead to modernize their API infrastructure. The company had legacy PHP APIs creating bottlenecks for feature development and system performance. My mandate was to migrate to Node.js while establishing architectural standards.

Over 4 years, I led the architecture migration, mentored team members, and established clean architecture practices that became company standards.

The Challenge

  • ▪ Legacy PHP APIs: Slow response times creating poor developer experience and bottlenecks for feature releases
  • ▪ Inconsistent patterns: No standardized approach to API development across microservices
  • ▪ Documentation scattered: API specs lived in multiple places, making onboarding difficult
  • ▪ Team coordination: Limited knowledge sharing between backend engineers on emerging best practices

The Solution

1. API Migration to Node.js

Spearheaded the systematic migration of critical PHP APIs to Node.js. Rewrote price request and order creation flows, which are at the core of Sendy's business logic.

Impact: 90% improvement in API response times, 25% faster request processing

2. Payload Optimization

Refactored request/response payloads to eliminate redundant data. Implemented selective field inclusion and response compression.

Impact: 30% smaller JSON payloads, reduced bandwidth costs

3. Clean Architecture & SOLID Principles

Applied Object-Oriented Programming and SOLID principles throughout the migration. Established clear separation of concerns between routing, business logic, and data layers.

Impact: 50% faster bug resolution, easier onboarding for new developers

4. Centralized API Documentation

Consolidated all API specifications into a single OpenAPI documentation hub. Made specs accessible from all microservices through a unified interface.

Impact: Improved developer experience, reduced onboarding time

5. Knowledge Sharing & Team Leadership

Organized regular pair programming sessions on Discord. Mentored team members on Node.js best practices, clean architecture, and code reviews.

Impact: Elevated team capabilities, established architectural standards company-wide

6. Partner Onboarding Refactor

Streamlined partner acquisition flow through backend refactoring. Simplified authentication and data collection workflows, enabling faster frontend user experience.

Impact: 40% reduction in partner onboarding time

Key Learnings

  • ▪ Architecture matters: Clean architecture principles aren't just nice-to-have; they directly impact team velocity and system reliability
  • ▪ Documentation is critical: Centralizing API specs dramatically improved developer experience and reduced friction
  • ▪ Leadership through mentorship: The biggest impact came from leveling up the team, not just writing code myself
  • ▪ Incremental migration works: Migrating piece-by-piece rather than a big rewrite reduced risk and kept the system running
